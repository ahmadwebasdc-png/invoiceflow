# InvoiceFlow — Local Invoice Generator

A responsive invoice-management starter built with HTML, CSS, Vanilla JavaScript, Express, and persistent JSON-file storage. It includes an invoice editor, automatic totals, invoice CRUD, client management, dashboard metrics, reports, settings, print/PDF export, and Node test-runner tests.

## Requirements

- Node.js 20 or newer (LTS recommended)
- npm
- Internet access for CDN assets (Lucide icons, Chart.js, html2pdf.js, and Google Fonts)

## Run on Windows with VS Code

1. Install Node.js LTS from https://nodejs.org/.
2. Open this folder in VS Code.
3. Open **Terminal → New Terminal**.
4. Verify installation:

   ```bash
   node -v
   npm -v
   ```

5. Install packages:

   ```bash
   npm install
   ```

6. Copy `.env.example` to `.env`. Windows PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

7. Start the server:

   ```bash
   npm start
   ```

8. Open **http://localhost:3000**. Do not open the HTML files directly with `file://`; the app uses the Express API.

For automatic restart during development, run `npm run dev`.

## Run tests

```bash
npm test
```

Tests cover calculation rules and JSON storage persistence. The API/browser end-to-end workflow has not been automatically browser-tested in this deliverable.

## Storage

The app uses JSON files in `server/data` by default. It creates `invoices.json`, `clients.json`, and `settings.json` automatically. Data persists across restarts. Back up this directory regularly. The write service serializes writes per collection and uses temporary-file replacement.

This deliverable intentionally uses JSON storage only; MongoDB/Mongoose is not implemented. Do not switch to MongoDB just by changing an environment variable. `STORAGE_MODE` is reserved in the example configuration for future extension; the current server logs its JSON storage location.

## Main features

- Responsive landing page and workspace navigation
- Create, read, update, and delete invoices
- Unique invoice numbers generated by the server for new invoices
- Server-side validation and total recalculation
- Item quantity, price, tax, and fixed discounts; invoice-level fixed or percentage discount
- Currency-aware formatting (no cross-currency aggregation)
- Draft, Pending, Paid, and derived Overdue statuses
- Client CRUD and protection against deleting clients referenced by invoices
- Dashboard and revenue reports based on saved invoices
- CSV export of invoice records
- PDF download from the editor/preview using html2pdf.js CDN; print fallback
- Business defaults stored on the server

## Calculation policy

- Line gross = quantity × unit price.
- Item discount is fixed per line, capped at that line's gross.
- Item tax is calculated after the item discount.
- Invoice-level discount is subtracted after item tax; percentage invoice discounts use taxable subtotal.
- Monetary values are rounded to two decimal places for display and persisted calculations.
- Backend recalculates all totals and does not trust frontend totals.
- Paid revenue uses `paidAt`; legacy paid records without `paidAt` use `updatedAt` as a fallback in the monthly chart.

## Important limitations

- Single-user local application; there is no authentication, authorization, user isolation, email delivery, online payment processing, or cloud sync.
- Do not deploy publicly or store real sensitive customer information without implementing authentication/authorization, backups, and a security review.
- JSON storage is appropriate for a local starter, not concurrent multi-user production traffic.
- Business logo upload is not included in this initial version.
- Client snapshots are saved on invoices, so edits to a client do not rewrite old invoice records.
- PDF generation depends on the CDN library and browser rendering; verify exported PDFs for your actual business documents.
- Invoice status is stored as Draft/Pending/Paid; Overdue is derived from the due date for unpaid invoices.
- Currency conversion is not included.
